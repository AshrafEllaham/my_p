# مرجع رحلة التاجر — سعي

> مرجع وظيفي مبني على الشاشات المعتمدة فعليًا داخل `preview.html` بتاريخ 28 سبتمبر 2026. عند اختلافه مع تنفيذ شاشة لاحق، تُراجع الشاشة ثم يُحدّث هذا الملف و`DESIGN_REFERENCE.md` معًا.

## 1. فكرة تجربة التاجر

يمنح سعي التاجر مساحة تشغيل موحدة لإدارة متجره ومنتجاته ومخزونه وطلبات الاستلام، ثم متابعة المبيعات والعملاء والتسويات. كما يستطيع التاجر تنشيط متجره من خلال الإعلانات والكوبونات والمسابقات، والتواصل مع العملاء من داخل التطبيق.

القيمة الأساسية للتاجر:

- إضافة المنتجات وتحديث بياناتها ومخزونها من مكان واحد.
- استقبال طلبات الشراء ومتابعتها حتى الاستلام من الفرع.
- إدارة الاسترجاع والتواصل مع العميل وتسجيل القرار المالي.
- إنشاء إعلانات وكوبونات ومسابقات وقياس أدائها.
- متابعة المبيعات والتسويات والتقارير والمستندات.
- إدارة بيانات المتجر والعملاء والموظفين والصلاحيات والسياسات.

## 2. ثوابت الرحلة

- اللغة عربية واتجاه الواجهة `RTL`.
- التنقل الرئيسي للتاجر: **الرئيسية — المنتجات — الطلبات — الإعلانات — الحساب**.
- لا يوجد توصيل في المرحلة الحالية؛ تنفيذ الطلب ينتهي باستلام العميل من المتجر.
- كل منتج له مخزون وسعر موحدان، بلا مقاسات أو ألوان أو فروع متعددة داخل رحلة الشراء الحالية.
- إنشاء المتجر لا يطلب سجلًا تجاريًا أو بطاقة ضريبية ما لم يطلب المستخدم إضافتهما صراحة.
- QR المتجر دائم ومرتبط بمعرّف المتجر، ولا يتغير عند تعديل اسم المتجر.
- سياسات الحجز والاسترجاع والاستبدال يحددها التاجر، ثم تظهر للمستخدم قبل الدفع وفي تفاصيل الطلب.
- الأزرار الرئيسية سوداء، وتستخدم ألوان الحالة للنجاح والتحذير والخطأ والمعلومات.
- كروت المسابقات والكوبونات تحمل خط حالة رأسيًا مستقيمًا بعرض `3px` ملاصقًا للحافة اليمنى بطول الكارد كاملًا ومن دون انحناء مستقل.

## 3. الخريطة العامة

```text
البداية
  └─ تسجيل الدخول / إنشاء حساب
       └─ OTP → الموقع → نوع الحساب «تاجر» → إعداد المتجر
                                            └─ لوحة التشغيل
                                                 ├─ المنتجات → إضافة/تعديل → مخزون → تحليل
                                                 ├─ الطلبات → تفاصيل → تجهيز → استلام
                                                 │                         └─ استرجاع
                                                 ├─ الإعلانات → إنشاء → مراجعة ودفع → أداء
                                                 ├─ المسابقات → تفاصيل → إدخال الإجابة الصحيحة → سحب
                                                 ├─ الكوبونات → إنشاء/تعديل → تفاصيل واستخدام
                                                 └─ الحساب
                                                      ├─ المالية والتقارير والمستندات
                                                      ├─ العملاء والموظفون
                                                      └─ المتجر والتقييمات والسياسات والنشاط
```

## 4. البداية وإنشاء حساب التاجر

### 4.1 رحلة التاجر الجديد

1. `00-splash.html` — تعريف سريع بهوية سعي والبدء.
2. `00-splash-01.html` — توضيح اكتشاف المتاجر الموثوقة، مع التخطي أو المتابعة.
3. `00-splash-02.html` — توضيح الطلب والاستلام من المتجر، ثم تسجيل الدخول.
4. `01-login.html` — تسجيل الدخول بالهاتف أو البريد، أو Google وApple.
5. `02-signup.html` — الهاتف والبريد وكلمة المرور وتأكيدها.
6. `03-verify-otp.html` — إدخال رمز من أربع خانات وإعادة الإرسال بعد العداد.
7. `05-profile-setup.html` — اختيار الدولة والمحافظة أو التخطي.
8. `04-account-type.html` — اختيار «حساب تاجر».
9. `06-distributor-setup.html` — غلاف المتجر، الشعار، الاسم، التصنيف والوصف، ثم بيانات مسؤول المتجر ورقم التسجيل ومستند إثبات النشاط وحساب التسوية.
10. `17-distributor-dashboard.html` — نقطة الدخول الأساسية بحالة «قيد المراجعة» حتى اعتماد بيانات المتجر، مع بقاء إعداد المحتوى متاحًا وعدم قبول مبيعات فعلية قبل التفعيل.

يمكن للتاجر العودة لاحقًا لتحديث بيانات العرض من `20-distributor-store-profile.html`، وتبقى بيانات التفعيل والتسوية محمية عن الملف العام.

### 4.2 تسجيل الدخول واستعادة كلمة المرور

- الحساب التجاري المكتمل ينتقل من `01-login.html` إلى لوحة تشغيل التاجر.
- الهوية الاجتماعية الجديدة تستكمل OTP والموقع ونوع الحساب وإعداد المتجر.
- مسار الاستعادة:

```text
01-login.html
  → 07-forgot-password.html
  → 03-verify-otp.html?flow=reset
  → 07-reset-password.html
  → 01-login.html
```

## 5. لوحة تشغيل التاجر

### `17-distributor-dashboard.html`

اللوحة هي ملخص اليوم ونقطة توزيع المهام، وتحتوي على:

- هوية المتجر، حالة فتحه، واختصاري الدردشات والإشعارات.
- مؤشرات سريعة للمبيعات والطلبات والمنتجات أو التنبيهات المهمة.
- إجراءات مباشرة لإضافة منتج أو إعلان وإدارة المسابقات.
- الطلبات الحديثة مع حالتها وفتح التفاصيل.
- ملخص أداء المنتجات والتقييمات والإعلانات.
- تنبيهات المخزون المنخفض والإجراءات التشغيلية التي تحتاج انتباهًا.

كل رقم مختصر يفتح مصدره التفصيلي؛ فلا تكون اللوحة بديلًا عن صفحات المنتجات والطلبات والتقارير.

## 6. المنتجات والمخزون

```text
17-distributor-dashboard.html

       ├─ 18-add-product.html
       ├─ 22-distributor-inventory.html
       └─ 18-distributor-product-details.html
```

### `18-distributor-products.html` — منتجاتي

- بحث وفلترة المنتجات حسب الحالة أو المخزون.
- عرض الصورة والاسم والسعر والمخزون والحالة.
- فتح تحليل المنتج أو تحريره.
- الوصول إلى إضافة منتج وإدارة المخزون.

### `18-add-product.html` — إضافة وتعديل منتج

- صور المنتج، الاسم، القسم والوصف.
- السعر والسعر قبل الخصم عند وجود عرض.
- كمية المخزون وحالة الإتاحة.
- نفس النموذج يخدم الإضافة والتعديل مع تحميل بيانات المنتج عند التحرير.
- الحفظ يتحقق من الحقول المطلوبة والأرقام، ثم يعكس التغيير في القوائم والتفاصيل.

### `22-distributor-inventory.html` — إدارة المخزون

- بحث وفلترة المنتجات حسب مستوى المخزون.
- تعديل الكمية بسرعة مع منع القيم السالبة.
- إبراز المخزون المنخفض والمنتهي.
- أي تحديث ينعكس على صفحة المنتج وإمكانية شراء المستخدم.

### `18-distributor-product-details.html` — تحليل أداء المنتج

- بيانات المنتج وحالته ومخزونه الحالي.
- مؤشرات المبيعات والطلبات والإيراد والتقييم.
- فتح التقييمات وتعديل بيانات المنتج.

## 7. الطلبات والتنفيذ والاستلام

```text
طلب مدفوع من المستخدم
  → جديد / تم التأكيد
  → جاري التجهيز
  → جاهز للاستلام
  → طلب تأكيد الإتمام من المستخدم عن بُعد أو التحقق من QR/الكود حضوريًا
  → مكتمل
       ├─ تقييم موثق
       └─ طلب استرجاع عند السماح
```

### `21-distributor-orders.html` — طلبات المتجر

- البحث في الطلبات والتصفية حسب الحالة.
- إظهار رقم الطلب والعميل والمنتج والقيمة والوقت والحالة.
- فتح التفاصيل أو التواصل مع العميل.
- الحالات الحالية منفصلة بوضوح عن المكتملة والملغاة والمرتجعة.

### `21-distributor-order-details.html` — تفاصيل الطلب

- بيانات الطلب والعميل والمنتج والدفع والفرع.
- خط زمني للحالة مع الإجراء المتاح فقط في المرحلة الحالية.
- نقل الطلب من التأكيد إلى التجهيز ثم الجاهزية، ثم طلب تأكيد الإتمام من المستخدم.
- لا يستطيع التاجر إكمال الطلب منفردًا: الإتمام يكون بتأكيد المستخدم داخل التطبيق عند التعامل عن بُعد، أو بإدخال كود الاستلام عند التسليم الحضوري.
- يستطيع المستخدم إيقاف الإتمام والإبلاغ عن مشكلة؛ ينتقل الطلب للمراجعة بدل إغلاقه.
- `23-distributor-disputes.html` يجمع النزاعات المفتوحة، ويتيح طلب معلومات إضافية أو اعتماد الإتمام أو رد المبلغ، مع إشعار المستخدم وتحديث المالية مرة واحدة.
- فتح المحادثة مع العميل عند وجود استفسار.

### قواعد تنفيذ الطلب

- لا يُعاد خصم قيمة الطلب عند تحديث حالته.
- لا يمكن إكمال الطلب قبل أن يصبح جاهزًا للاستلام.
- الإلغاء أو رد المبلغ يسجلان مرة واحدة فقط في المحفظة والحركة المالية.
- تغيير الحالة ينشئ إشعارًا مناسبًا للمستخدم ويظهر في سجل النشاط.

## 8. المرتجعات والاسترداد

### `23-distributor-returns.html`

- قائمة طلبات الاسترجاع مع فلترة الحالة.
- عرض السبب ووصف العميل والصور والمبلغ المتوقع.
- فتح الطلب الأصلي والمحادثة قبل اتخاذ القرار.
- قبول أو رفض الطلب مع ملاحظة واضحة للعميل.
- القبول يبدأ تنسيق إعادة المنتج أو الاستبدال، ولا يرد المبلغ وحده.
- بعد استلام المنتج وفحصه يسجل التاجر الإتمام؛ عندها فقط يعاد المبلغ إلى محفظة المستخدم مرة واحدة أو يسجل اكتمال الاستبدال.
- حالات الرحلة: **قيد المراجعة — مقبول — مرفوض — تم رد المبلغ**.

قرار التاجر يجب أن يلتزم بسياسة المتجر التي كانت معروضة للمستخدم عند الشراء.

## 9. الإعلانات والباقات

```text
19-distributor-ads.html
  → 19-add-ad.html

  → distributor-ad-details.html
```

### `19-distributor-ads.html` — الإعلانات والباقات

- ملخص الإعلانات حسب الحالة: مسودة، قيد المراجعة، مجدول، نشط، مكتمل أو مرفوض.
- فتح إعلان موجود أو إنشاء إعلان جديد.
- هذه الوحدة موسومة «مؤجلة» في ترتيب التنفيذ الحالي، لكنها جزء موثق من فكرة المشروع والـpreview.

### `19-add-ad.html` — إضافة إعلان

- اختيار هدف الإعلان والمنتج أو العرض المرتبط به.
- رفع المادة البصرية وإدخال النص المختصر وزر الإجراء.
- تحديد موضع الظهور والفترة أو الجدول والميزانية/الباقة.
- حفظ المسودة أو الانتقال إلى المراجعة.

### `19-ad-review.html` — مراجعة ودفع الإعلان

- معاينة الإعلان كما سيظهر للمستخدم.
- مراجعة الموضع والمدة والتكلفة.
- الرجوع للتعديل أو تأكيد الدفع والنشر.

### `distributor-ad-details.html` — تفاصيل الإعلان

- الحالة والفترة والمادة المستخدمة.
- مؤشرات المشاهدات والنقرات والتفاعل أو الطلبات المنسوبة.
- الإجراءات المتاحة حسب الحالة، مثل التعديل أو الإيقاف أو إعادة الاستخدام.

إعلان صفحة القسم يستخدم نفس شكل إعلان الرئيسية ونفس نسبة العرض إلى الارتفاع، مع اختلاف سياق القسم فقط.

## 10. المسابقات والسحب

```text
20-distributor-competitions.html
  → إنشاء مسابقة: عنوان + سؤال + جائزة + موعد انتهاء
  → 20-distributor-competition-details.html
  → إدخال الإجابة الصحيحة وقت السحب
  → مطابقة المشاركات
  → اختيار فائز عشوائي من المؤهلين
  → حفظ النتيجة وإعلانها
```

### `20-distributor-competitions.html` — مسابقاتي

- ملخص عدد المسابقات النشطة والمشاركات وعمليات السحب.
- فلاتر: الكل، نشطة، وتم السحب/منتهية.
- كل كارد يعرض العنوان والسؤال والموعد وعدد المشاركات والحالة.
- خط الحالة الرأسي يمتد بطول الكارد كاملًا.
- قائمة ثلاث نقاط في كل كارد تحتوي على **تعديل** و**حذف**.
- إنشاء مسابقة جديدة من داخل محتوى الصفحة، من دون زر إضافة منفصل في الهيدر.

### `20-distributor-competition-details.html` — التفاصيل والسحب

- عنوان المسابقة وسؤالها وجائزتها وموعدها وحالتها.
- عدد المشاركات وقائمة الإجابات أو ملخصها.
- قائمة ثلاث نقاط في الهيدر تحتوي على **تعديل** و**حذف**.
- عند بدء السحب يكتب التاجر الإجابة الصحيحة التي ستتم المقارنة على أساسها.
- تطبع الإجابات قبل المقارنة بتجاهل التشكيل، اختلاف أشكال الألف، والمسافات الزائدة.
- يحسب النظام المشاركات المطابقة، ثم يختار فائزًا عشوائيًا من المطابقين فقط.
- إذا لم توجد إجابة مطابقة، تظهر نتيجة واضحة من دون اختيار فائز غير مؤهل.
- تحفظ الإجابة الصحيحة والفائز وتوقيت السحب، ولا يعاد السحب تلقائيًا بعد تثبيت النتيجة.

## 11. كوبونات الخصم

```text
20-distributor-coupons.html
  ├─ إنشاء/تعديل كوبون
  └─ 20-distributor-coupon-details.html
```

### `20-distributor-coupons.html` — كوبونات الخصم

- فلاتر: الكل، النشطة، المتوقفة والمنتهية.
- إنشاء وتعديل وحذف وإيقاف أو إعادة تفعيل الكوبون.
- خصم بنسبة مئوية أو مبلغ ثابت.
- تحديد الكود والحد الأدنى للطلب وتاريخ الانتهاء وحدود الاستخدام.
- تحديد إجمالي مرات الاستخدام والحد الأقصى لكل مستخدم، وتحويل الحالة إلى «مستنفد» تلقائيًا عند بلوغ الإجمالي.
- خط الحالة الرأسي مستقيم بطول الكارد كاملًا، مطابق لخط كارد المسابقة.

### `20-distributor-coupon-details.html` — تفاصيل الكوبون

- الكود والحالة ونوع الخصم وقيمته.
- الصلاحية والحد الأدنى وحدود الاستخدام.
- مؤشرات مرات الاستخدام والخصم والمبيعات المتأثرة.
- فتح التعديل أو الرجوع إلى قائمة الكوبونات.

يتحقق الدفع من أن الكوبون يتبع نفس المتجر، نشط، غير منتهٍ، ولم يتجاوز حد الاستخدام، وأن الطلب يحقق الحد الأدنى.

## 13. العملاء والموظفون

### `23-distributor-customers.html` — إدارة العملاء

- البحث في عملاء المتجر وعرض عدد الطلبات وإجمالي الإنفاق وآخر نشاط.

## 14. الحساب وبيانات المتجر

### `20-distributor-account.html` — حساب التاجر

بوابة الوصول إلى:

- المالية والكوبونات والمسابقات والتقييمات والمرتجعات.

- العنوان وموقع الاستلام وحالة المتجر، من دون جدول ساعات عمل.
- عرض QR المتجر الدائم المرتبط بالمعرّف، لا بالاسم.
- التعديل لا يغير تاريخ الطلبات أو الروابط المرتبطة بمعرّف المتجر.

### `merchant-activation-status.html` — حالة تفعيل المتجر

- يعرض حالات قيد المراجعة والقبول والرفض بوضوح.
- عند الرفض يظهر السبب وإمكانية رفع مستند بديل وإعادة الإرسال.
- عند القبول يتاح استقبال الطلبات المدفوعة والتسويات.

### `20-distributor-reviews.html` — تقييماتي

- متوسط التقييم وتوزيع النجوم.
- تقييمات العملاء الموثقة المرتبطة بطلبات مكتملة.
- فتح المنتج أو الطلب لفهم سياق التقييم.

### `24-distributor-policies.html` — سياسات المتجر

- مدة حجز الطلب الجاهز.
- شروط الاسترجاع والاستبدال والإلغاء.
- معاينة النص الذي سيظهر للمستخدم قبل حفظه.
- التغييرات الجديدة تطبق على الطلبات اللاحقة مع حفظ نسخة السياسة المرتبطة بكل طلب قائم.

## 15. الإشعارات وسجل النشاط

## 17. نموذج الحالات المشتركة

| المجال | الحالات الأساسية |
| --- | --- |
| المنتج | متاح، مخزون منخفض، نفد المخزون، مخفي |
| الطلب | تم التأكيد، جاري التجهيز، جاهز للاستلام، مكتمل، ملغي |
| الاسترجاع | قيد المراجعة، مقبول، مرفوض، تم رد المبلغ |
| الإعلان | مسودة، قيد المراجعة، مجدول، نشط، مكتمل، مرفوض |
| المسابقة | نشطة، منتهية، تم السحب |
| الكوبون | نشط، متوقف، منتهي |
| التسوية | قيد المعالجة، مكتملة، تحتاج مراجعة |

كل انتقال حالة يجب أن يحدث من إجراء صريح، ويحفظ وقته ومنفذه، ويحدث الصفحات المرتبطة ويصدر الإشعار المناسب.

## 18. قواعد القبول الوظيفي

- يبدأ التاجر المكتمل من لوحة التشغيل، ولا يحول إلى رئيسية المستخدم.
- تظهر تعديلات المنتج والمخزون فورًا في تجربة المستخدم.
- لا يسمح بأي كمية مخزون سالبة أو سعر غير صالح.
- لا يمكن إكمال طلب قبل مرحلة «جاهز للاستلام» والتحقق من الاستلام.
- لا ينفذ الإلغاء أو الاسترداد المالي أكثر من مرة.
- لا يختار سحب المسابقة إلا من الإجابات المطابقة للإجابة الصحيحة التي أدخلها التاجر.
- تعرض كروت المسابقات والكوبونات خط الحالة المستقيم بطول الكارد كاملًا.
- تحوي قائمة الثلاث نقاط للمسابقة «تعديل» و«حذف» في القائمة والتفاصيل.
- يطبق الكوبون فقط على متجره وضمن صلاحيته وحدوده.
- تعرض إعلانات الأقسام للمستخدم بنفس شكل إعلان الرئيسية.
- لا يتغير QR المتجر عند تعديل الاسم أو الصور.
- تدعم القوائم حالات التحميل والفراغ والخطأ وانقطاع الاتصال، مع إعادة المحاولة عند الحاجة.
- تظهر رسائل نجاح أو خطأ واضحة بعد كل حفظ أو حذف أو تغيير حالة.
- تعمل الواجهة من دون خروج أفقي عند `440×956` و`393×852` و`360×800`.

## 19. الحالة المشتركة داخل النموذج الأولي

- `screens/merchant-state.js`: المصدر المحلي المشترك لبيانات التاجر مثل المنتجات والطلبات والإعلانات والمسابقات والكوبونات والمالية.
- `screens/user-state.js`: يربط أثر إجراءات التاجر بتجربة المستخدم، خصوصًا المنتجات والطلبات والكوبونات والمسابقات والمحفظة.
- `screens/merchant-ui-states.css` و`screens/merchant-ui-states.js`: حالات التحميل والخطأ وانقطاع الاتصال والتأكيدات ورسائل النجاح والوضع الداكن.
- `screens/merchant-operations.css` و`screens/merchant-backoffice.css`: مكونات التشغيل والإدارة المشتركة بين صفحات التاجر.

هذا الملف يصف **ماذا يفعل التاجر ولماذا**. أما الهوية والمقاسات والأنماط البصرية العامة فمرجعها `DESIGN_REFERENCE.md`، وجرد الشاشات الحي مرجعه `preview.html`.
